# Corpus measurements

Generated by `npm run docs` from `docs/MEASUREMENTS.json`, which is produced by
`npm run measure` over `corpus/configs.json`. Nothing here is estimated by hand.

## Where the corpus comes from

`scripts/collect-corpus.cjs` asks the GitHub code search API for
`filename:.browserslistrc`, takes the first three pages of hits, keeps files whose path ends in
`.browserslistrc`, and stores the repository, path, canonical URL, collection date and a SHA-256 of
the retrieved text. Collection date: **{{corpus.collectedAt}}**, **{{corpus.total}} files**,
**{{corpus.shapes}} distinct query shapes**, **{{corpus.clauses.total}} clauses**
(median {{corpus.clauses.median}} per file, max {{corpus.clauses.max}}).

Re-collect with `node scripts/collect-corpus.cjs` (needs an authenticated `gh` CLI). Anything below
changes with the sample, so both the script and the data are in the repository.

final list.

TT001 does not fire for `not` clauses; those are TT003, which is why the two counts do not overlap.
TT007 is the only rule that depends on `--coverage` being requested, so its count is a lower bound.

The most frequent TT001/TT003 clause texts in this sample are `not IE 11` (already excluded by
`defaults`), `not op_mini all`, `not dead` and a repeated `> .5%` — all cases where a line looks
meaningful and changes nothing.

## Coverage

Median coverage of the resolved target list: **{{corpus.coverage.median}}%** of global usage, range
**{{corpus.coverage.min}}%–{{corpus.coverage.max}}%** across {{corpus.traceable}} configs. The low
end is not a defect: it is configs pinning one old version (`ie 9`), or `current node`, which caniuse
has no usage data for. The high end is configs using `>0%`-style queries or regional data
(`> 0.5% in FI`).
