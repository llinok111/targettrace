# Corpus measurements

Generated by `npm run docs` from `docs/MEASUREMENTS.json`, which is produced by
`npm run measure` over `corpus/configs.json`. Nothing here is estimated by hand.

## Where the corpus comes from

`scripts/collect-corpus.cjs` asks the GitHub code search API for
`filename:.browserslistrc`, takes the first three pages of hits, keeps files whose path ends in
`.browserslistrc`, and stores the repository, path, canonical URL, collection date and a SHA-256 of
the retrieved text. Collection date: **2026-10-26**, **276 files**,
**121 distinct query shapes**, **1381 clauses**
(median 4 per file, max 55).

Re-collect with `node scripts/collect-corpus.cjs` (needs an authenticated `gh` CLI). Anything below
changes with the sample, so both the script and the data are in the repository.

## Where order-free attribution fails

Comparing the ledger against a naive "union the positive clauses, subtract the negative ones"
reading over the same 268 configs: **27 disagreements
(10.1%)**.

- `opensearch-project/OpenSearch-Dashboards:.browserslistrc` — Firefox > 0 and last 2 years and > 0.01% | Chrome > 0 and last 2 years and > 0.01% | Safari > 0 and last 2 years and > 0.01% | Edge > 0 and last 1 years and > 0.01% | Opera > 0 and last 2 years and > 0.01% | > 0.2% | not op_mini all | not and_uc < 100 | not android < 100 | not dead
  - actual 63 browsers vs order-free 620; 6 extra browsers (e.g. and_qq 14.9, android 156, chrome 10)
- `team-innovation/vue-sfc-rollup:templates/single/_template.browserslistrc` — current node | last 2 versions and > 2% | ie > 10
  - actual 3 browsers vs order-free 36; 6 extra browsers (e.g. and_ff 158, and_qq 14.9, and_uc 15.5)
- `team-innovation/vue-sfc-rollup:templates/library/_template.browserslistrc` — current node | last 2 versions and > 2% | ie > 10
  - actual 3 browsers vs order-free 36; 6 extra browsers (e.g. and_ff 158, and_qq 14.9, and_uc 15.5)
- `rstudio/learnr:.browserslistrc` — last 2 versions | not dead | > 0.2% | Firefox ESR | phantomjs 2.1 | IE 11
  - actual 57 browsers vs order-free 56; missing from the order-free reading: ie 11
- `digital-analytics-program/gov-wide-code:.browserslistrc` — last 2 versions | not dead | > 0.1% | Firefox ESR
  - actual 71 browsers vs order-free 70; missing from the order-free reading: ie 11
- `nateplusplus/pushin:.browserslistrc` — defaults | last 2 versions | not dead | > 0.2% | ie > 10
  - actual 56 browsers vs order-free 55; missing from the order-free reading: ie 11

Both failure modes are visible above: ` and ` clauses are intersections (not unions), and a browser
removed by `not` can be re-added by a later clause, so the order in which clauses appear changes the
final list.

## Rule hits

| TT001 dead-clause | 71 | 71 |

| TT007 coverage-collapse | 1 | 1 |

TT001 does not fire for `not` clauses; those are TT003, which is why the two counts do not overlap.
TT007 is the only rule that depends on `--coverage` being requested, so its count is a lower bound.

The most frequent TT001/TT003 clause texts in this sample are `not IE 11` (already excluded by
`defaults`), `not op_mini all`, `not dead` and a repeated `> .5%` — all cases where a line looks
meaningful and changes nothing.

## Coverage

Median coverage of the resolved target list: **83.55%** of global usage, range
**0%–97.49%** across 268 configs. The low
end is not a defect: it is configs pinning one old version (`ie 9`), or `current node`, which caniuse
has no usage data for. The high end is configs using `>0%`-style queries or regional data
(`> 0.5% in FI`).
